# Zone file

The zone file is the one piece of state secdns serves. In the suite it is **generated by
SecDeploy** from `topology.toml` (one record per component → the address of the resource that
hosts it), but it is a plain text file you can also write or edit by hand.

## Format

One record per line: `<name> <type> <value>`. Blank lines and `#` comments (whole-line or
trailing) are ignored.

```
# name          type   value
secrouter       A      10.0.0.5
secllm          A      10.0.0.6
secrecorder     A      10.0.0.5
_acme-challenge.secrouter   TXT   "validation-token"
```

- **name** — short (relative to `--domain`) or a full FQDN; both normalize to the same key.
  `secrouter` and `secrouter.sec.internal` are equivalent when the domain is `sec.internal`.
- **type** — `A` (IPv4), `AAAA` (IPv6), or `TXT`.
- **value** — a dotted-quad, an IPv6 address, or (for `TXT`) text; surrounding quotes are
  stripped.

## Validating

Parse and print a zone file without starting the server:

```bash
uv run secdns check-zone --domain sec.internal --zone zones/secdns.zone
```

```
zone sec.internal: 8 record(s) from zones/secdns.zone
  secrouter.sec.internal             A     10.0.0.5
  secllm.sec.internal                A     10.0.0.6
  …
```

A malformed line (fewer than three fields, or an unsupported type) is a hard error naming the
file and line number.

## Reloading

After the zone file changes, reload without restarting:

- send `SIGHUP` to the process (`kill -HUP <pid>`), or
- click **Reload zone** in the [console](console.md), or `POST /reload`.

SecDeploy uses this to refresh the zone after a topology change.

## TXT and DNS-01

`TXT` support is here so SecCert can later publish `_acme-challenge.<name>` records for ACME
**DNS-01** — issuing certificates for wildcard or otherwise-unreachable internal hosts in a
closed network. That flow is on the suite roadmap; the record type is already served.
